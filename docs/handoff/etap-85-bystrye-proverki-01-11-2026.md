# Этап 85: быстрые проверки GitHub

Дата: 01.11.2026. Ветка: `etap-85-bystrye-proverki`. В плане доработок после аудитов этот пункт назван этапом 84, но номер 84 уже занят веткой карты сроков, поэтому здесь он идёт как этап 85.

## Что было не так

Поток `.github/workflows/ci.yml` держал всё тяжёлое в одной работе `test`, строго по очереди: `npm ci`, `prisma migrate deploy`, типы, правила, правила на базе, сверка импорта Bord, сборка, установка браузера, сквозные тесты. Полный прогон занимал около 40 минут, и почти всё это время работа ждала сама себя.

Отдельно:

- сквозные тесты (53 файла, около 10 тысяч строк, две ширины экрана) шли одним потоком в одной работе и были самым долгим куском;
- сборка Next делалась один раз, но ничего не кэшировалось между прогонами;
- браузер Playwright качался заново каждый прогон;
- типы и правила без базы ждали в очереди за миграциями, хотя база им не нужна;
- прежний прогон по ветке не отменялся новым: при двух push подряд очередь удваивалась.

Кэш зависимостей npm (`cache: npm` в `actions/setup-node`) вопреки ожиданию был уже настроен в обеих работах, добавлять его не пришлось.

## Что сделано

Поток разложен на работы, которые идут одновременно:

- `lint` — линтер и сверка `eslint-suppressions.json`, без базы (как было);
- `tipy` — типы TypeScript и `npm test`, без базы: раньше ждали очереди в работе с базой;
- `baza` — `npm run test:db` и сверка импорта Bord на настоящей PostgreSQL;
- `sborka` — `npm run build` один раз на весь прогон, результат уходит артефактом `sborka-next` (упакован в tar, без `.next/cache`);
- `e2e` — сквозные тесты шестью частями одновременно, `playwright test --shard=N/6`, каждая часть со своей PostgreSQL и своей базой `weekly_e2e`, сборку берут готовой из `sborka`;
- `docker` — сборка образа, как было;
- `itog` — одна отметка на весь прогон: падает, если любая работа или любая часть сквозных тестов не прошла, была отменена или пропущена.

Кэши между прогонами: зависимости npm (было), сборка Next (`.next/cache`, ключ по `package-lock.json` и SHA с откатом на предыдущие сборки), браузер Playwright (`~/.cache/ms-playwright`, ключ по `package-lock.json`). При попадании в кэш браузера ставятся только системные пакеты (`playwright install-deps chromium`), сам браузер не качается.

Добавлена группа `concurrency` с отменой прежнего прогона по той же ветке.

Покрытие не тронуто. Все шаги прежней работы `test` остались, просто разошлись по работам. Конфиг Playwright не менялся: внутри части по-прежнему `fullyParallel: false`, `workers: 1` и те же две ширины, 1440 и 360. Деление на части сделано флагом командной строки, а не правкой тестов. Пропусков не добавлено, таймауты не менялись. Трассы упавших сквозных тестов по-прежнему выкладываются артефактом, теперь по одному на часть: `e2e-traces-chast-1` … `e2e-traces-chast-6` (имена артефактов в `actions/upload-artifact@v4` обязаны быть разными). `fail-fast: false` оставляет остальные части доработать, чтобы в одном прогоне было видно все падения, но любая упавшая часть роняет прогон.

Файлы в ветке: `.github/workflows/ci.yml`, `README.md` (раздел «Проверки на GitHub (этап 85)»), этот файл.

## Две находки, не связанные с этапом 85

Прогон по ветке красный, но ни одна из причин не в проверках. Упали два сквозных теста, оба из-за даты, и оба упали бы сегодня при любом устройстве потока:

1. `tests/e2e/weekly.spec.ts:203` ждёт подпись `/^Сохранён \d+ октября/`. Месяц в проверке записан буквами. Строку добавили 05.10.2026 (`git blame`), весь октябрь она проходила, а с 1 ноября подпись читается «Сохранён 1 ноября» и проверка падает. Тест упал в обоих видах, на ноутбуке и на телефоне, то есть в двух разных частях: это признак ошибки самого теста, а не взаимного влияния частей.
2. `tests/e2e/roadmap.spec.ts:275` при перетаскивании края полосы ждала `2026-12-10`, получила `2026-12-01`. Тест опирается на пиксельные расчёты в окне карты сроков, а окно строится от сегодняшнего дня. Уверенности меньше, чем в первом случае: это может быть и неустойчивый тест. Трасса лежит в артефакте `e2e-traces-chast-3`.

Тесты по условию этапа не правились. Обе находки стоит закрыть отдельно: в первом случае заменить месяц буквами на вычисление от текущей даты, во втором разобрать трассу.

## Чего в ветке нет

- Слоёвый кэш сборки образа Docker (`buildx` с `cache-from type=gha`). Работа `docker` не на самом долгом пути, а кэш слоёв образа занял бы большую часть десяти гигабайт кэша репозитория и вытеснял бы кэши npm, Next и браузера. Если `docker` окажется узким местом, это следующий шаг.
- Кэш самого `node_modules`. `npm ci` остался в каждой работе: ключ кэша не различает образы раннера (`ubuntu-24.04` и `ubuntu-latest`), а движки Prisma собраны под конкретный образ, поэтому один ключ на разные образы давал бы тихие поломки.
- Сведение отчётов частей в один (`--reporter=blob` и `merge-reports`). Сейчас каждая часть печатает свой список, этого достаточно; общий HTML-отчёт в проекте и так не публикуется.
- Триггеры не менялись: `push` и `pull_request` по-прежнему дают два прогона на ветку с открытым pull request. Это удваивает расход минут, но не время ответа.
- Разделение `tipy` на две работы (типы и правила отдельно) не делалось: вместе они укладываются в пару минут.
