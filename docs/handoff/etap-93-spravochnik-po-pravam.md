# Этап 93. Справочник в пределах доступа

Дата: 09.11.2026. База: main `f1e4f4b` (после PR #107). Отдельная ветка `etap-93-spravochnik-po-pravam`.

## Решение владельца

Всем доступны ФИО и должности действующих сотрудников. Составы weekly-команд — только в пределах доступа. Роли доступа и сведения об отключённых сотрудниках — только в управлении. Имена авторов доступной истории сохраняются. Владелец явно принял правило и разрешил два независимых ревью обоих исправлений готовности (этапы 92 и 93).

## Реализация

- Серверный `loadRegistry` требует явные `management` и `visibleTeams`: публичный DTO не содержит `role`/`active`, отключённых людей или скрытых связей команд. Свой профиль передаётся отдельно.
- Общие изменяемые PEOPLE/TEAMS больше не заполняются при отрисовке приложения. `RegistryContext` и замыкания lookup изолируют одновременно отображаемые справочники. Старые адаптеры остаются для unit-фикстур; стартовые персональные данные перенесены в тесты.
- Исторические подписи передаются рядом с уже разрешёнными данными: только slug, полное и короткое имя. Они не пополняют список кандидатов для назначения и не раскрывают роли, почту или состояние аккаунта.
- Переведены потребители имён в задачах, weekly, комментариях, встречах, просьбах, поиске, прогнозе и журнале. Дозагрузка истории задачи имеет собственный компонент с локальными подписями.
- Дополнительные пути выдачи сведений приведены к правилу: структура и дерево людей, публичный выбор профиля, сведения об инициативах и отчётах, аналитика, weekly-команды и их picker. Прямая ссылка на недоступную weekly-команду не раскрывает её состав. Имена скрытых родителей и текущие связи с отключёнными руководителями исключены.
- Существующие права на действия не расширяются. Исторические имена из недоступных зависимостей задачи не передаются.

## Проверки и ревью

Добавлены DB-тесты публичного и управленческого снимков, структуры, прямых адресов команд, аналитики, picker, исторических имён и скрытых зависимостей. Unit проверяет два перекрывающихся серверных рендера и локальное расширение подписей без изменения кандидатов. Браузер проверяет реальные ответы сервера одновременно для сотрудника/управления, отсутствие скрытых команд по прямому адресу и имена отключённых авторов комментария и истории на 1440/360.

Два независимых ревью нашли и помогли устранить пропущенные сериализаторы: отсутствие, история, зависимости, аналитика, focusTeam и picker. Финальная проверка конкретного коммита и полный GitHub-прогон фиксируются в PR после завершения. Не считать этот файл подтверждением выкладки.

Локальная PostgreSQL для проверок содержит только искусственные данные. Первый кластер с локалью C дал четыре ошибки русского поиска (разный регистр); проверка to_tsvector воспроизвела причину. В отдельном кластере с en_US.UTF-8 исходные проверки поиска прошли. Unit-тестам сетевого транспорта требуется разрешённый локальный listener; EPERM песочницы не является результатом проверки кода.
